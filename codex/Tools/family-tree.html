How this works

Reading. It reads every .md in Characters/ and parses the ## Relationships table. Only these Relation words build the tree:

parent · child · sibling · spouse · half-sibling · adoptive parent · adoptive child · step-parent · step-child
Common wordings are understood too - mother, dad, sister, wife, adopted son, and so on. Everything else ("rival", "owes her money") is kept in the file and shown in the sidebar, but is not drawn.

Building a tree. Drag a name from the left list onto someone in the tree - a menu asks how they're related, and both files are updated. Dropping on empty canvas links them to whoever the tree is centred on. Dropping the first character onto an empty canvas just starts the tree there. The sidebar form does the same thing with notes and a marker.

Writing. Adding or removing a relative edits only the ## Relationships table in the affected files. The rest of each file is untouched, and updated: is bumped. Reciprocal rows are written into the other person's file when that file exists.

People without files. A relative you name who has no .md yet appears as a dotted card. Use Create file in the sidebar to give them a real seed entry - that answers "Father" and "Youngest sister" from Arcy's backstory without inventing names.

Reading the tree. Switch between hourglass (ancestors and descendants), ancestors and descendants; cap how many generations show with the up/down steppers; and click the – under anyone to fold away everyone below them (the badge then shows how many are hidden). Other links draws the non-family rows - "rival", "owes her money" - as faint labelled curves.

How are two people related? Pick someone in the sidebar's How is … related to box, or right-click a card. You get the kinship (grandparent, cousin, aunt or uncle) and the exact chain it was derived from. Underneath is a free-text note - "blames him for selling the north field" - saved to a ## Relationship Notes section in the file. It's deliberately one-way: how Arcy feels about her grandfather is not how he feels about her.

Portraits come from main_ref, or the first image in art_folder if no ref is set. Nothing to configure - the fields already exist.

The ⚠ button lists anything contradictory: placeholder names two characters are unknowingly sharing, descent that loops back on itself, pairs recorded two incompatible ways, rows only one of the two files knows about. It never blocks you, and half-finished is a perfectly normal state.

Undoing. Every add, removal, and file creation is undoable - Ctrl+Z, the ↶ button, or the undo link in the message that pops up after each change. Ctrl+Shift+Z redoes. To remove one relationship, right-click a person in the tree and pick who to unlink from, or use the × beside the row in the sidebar - either way the mirrored row in the other person's file goes too. Discard throws away every unsaved change at once and re-reads what's on disk. Nothing touches your files until you press Save changes.

Browser support. Saving needs Chrome or Edge (File System Access API). In other browsers you can still load a folder read-only and download edited files individually.
